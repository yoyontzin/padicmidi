# Reproducibility — PAdicMIDI

## Reproduction commands

```bash
# 1. Build a clean environment (Python 3.13.3 used by the author).
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-pinned.txt
pip install -e .

# 2. Run the canonical pipeline:
bash scripts/reproduce.sh

# 3. Verify against the gold standard:
bash scripts/validate.sh
pytest tests/
```

## Random seed policy

Every CLI tool exposes `--seed` (default 42). The fixed seed is critical: the
exact reproduction of $\mathrm{Coh}_\pi(3,n)$ depends on the K-means
initialisation. Changing the seed within tolerances $\pm 0.01$ for $p=3$
remains compatible with the paper's claims, but breaks bit-equivalence of the
emitted CSVs.

## Memory considerations

For prime $p=5$, level $N_{\max}=4$ requires
$|S_{N_{\max}-1}| \cdot p^{N_{\max}} \cdot |S_{N_{\max}}| \cdot 13 = 625 \times 128 \times 625 \times 13 \approx 4.84$ GiB.
The default for $p=5$ is therefore $N_{\max}=4$ and the motor warns when
exceeded. Override with `--Nmax 3` on memory-constrained hosts.

## Reproducing on different platforms

On non-arm64 macOS or on Linux, expect minor drift at the 5th–6th decimal
place in $\mathrm{Coh}_\pi$. The structural floor $\mathrm{Coh}_\pi(p,n)=1/p$
remains exact because it is determined by the binary/ternary structure of the
input, not by floating-point order of operations.
